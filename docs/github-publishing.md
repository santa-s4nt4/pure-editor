# GitHub で記事を公開する

pure で公開を選んだ Markdown と参照画像だけを、記事専用の公開リポジトリへ保存します。
poin7s.com は pure から公開した記事の一覧と本文だけを読み込みます。Scrapbox 連携は廃止しており、以前の Scrapbox 記事はサイトに表示しません。元の Scrapbox の記事は削除しません。
About ページは pure でタイトルを `About` にして公開した記事を読み込みます。大文字・小文字は区別せず、同名が複数なら最終更新の新しい記事を使います。About 記事は Works・Memorandum・関連記事の一覧には表示しません。未公開・取り下げ時は「プロフィールは準備中です。」と表示します。
既存記事・新規記事はすべて初期状態で非公開です。今回、実際の記事を公開にはしていません。

## 最初の設定（Mac・iPhone）

公開先は [santa-s4nt4/pure-notes](https://github.com/santa-s4nt4/pure-notes)、ブランチは `main` です。空の公開一覧を用意済みです。

1. GitHub の [Fine-grained personal access tokens](https://github.com/settings/personal-access-tokens) を開き、**Generate new token** を選びます。
2. Resource owner を `santa-s4nt4` にします。名前は `pure-publishing` など。期限は運用に合わせて選び、期限切れ前に更新してください。
3. Repository access は **Only select repositories**、対象は **pure-notes だけ**にします。
4. Repository permissions の **Contents を Read and write** にします。Metadata の読み取りは自動で付きます。他の権限は不要です。
5. トークンを発行し、pure の設定（Mac は `⌘ ,`、iPhone は `⋯` の上部にある「設定」）を開きます。
6. 「GitHub に公開」に、リポジトリ `santa-s4nt4/pure-notes`、ブランチ `main`、発行したトークンを入力し「設定を保存」を押します。

トークンは端末ごとのキーチェーンに保存します。Markdown、R2、GitHub、サイトの JavaScript、設定 JSON には保存しません。Mac と iPhone ではそれぞれ設定してください。ブラウザの開発プレビューでは GitHub 公開を利用できません。

このトークンは選択したリポジトリ内の内容を書き換えられるため、アプリのコードや他の文書のリポジトリを対象に追加しないでください。接続の解除は設定のトークン欄を空にして保存します。接続を解除しても、すでに公開された記事は取り下げられません。

## 公開・非公開を切り替える

記事を開き、**`⋯` →「公開範囲」のスイッチをオン**にします。macOS の `⋯` はウィンドウ右上、iPhone は右下です。`⌘ L` のコマンド一覧から「この記事を公開する」も選べます。
本文・タグ・記事から参照するローカル画像が GitHub に保存されます。公開中の記事を編集すると、自動保存後に公開先も更新します。

- `[art work]` / `[client work]` がある記事: poin7s.com の **Works**。
- それ以外の記事: **Memorandum**。タグを付けなくても表示します。
- `[tag]`、見出し、箇条書き、チェックリスト、画像、YouTube・Vimeo を表示できます。リンクは `[URL 表示名]`・`[表示名 URL]` のどちらでも書けます。
- 記事の URL は `https://poin7s.com/viewer.html?post=<記事ID>`。タイトルを変更しても URL は変わりません。
- トップ画面の「すべて / 非公開 / 公開」で公開設定を絞り込めます。

**`⋯` の公開スイッチをオフ**にするか「この記事を非公開にする」を選ぶと、公開一覧・本文・他の公開記事が使っていない画像を、同じコミットで取り下げます。ローカルの記事は残ります。`⋯` の「この記事を削除」から記事を削除できます。公開記事をアプリから削除するときも、先に取り下げます。接続できなければ削除を中断します。元に戻した記事は非公開です。

**公開リポジトリの Git 履歴は誰でも閲覧できます。非公開に戻しても、過去のコミット、GitHub のキャッシュ、第三者が保存した内容まで消えるわけではありません。** 公開前に本文・タグ・画像を確認してください。コードブロック内の画像記法や、参照していないローカル画像はアップロードしません。外部 URL の画像はその URL をそのまま利用します。

Paper 文書は対象外です。Dropbox の会社文書を自動で GitHub へ送ることはありません。この記事公開機能を使う場合は、別の Markdown 記事として内容を確認してから公開してください。

## 同期と反映の確認

設定の「GitHub に公開」に状態が表示されます。「公開設定あり」は端末内の希望状態です。**「公開先は最新です」になるまでは、公開・取り下げ・編集の反映が完了したとは限りません。** ネットワークやトークンの問題がある場合、本文と公開希望はローカルに残ります。再接続・再起動時と約1分ごとに再試行します。`⌘ L` / `⋯` →「公開先を同期する」でも再試行できます。

Mac と iPhone で同じ記事を扱う場合は R2 の端末間同期も有効にしてください。公開設定は Markdown 先頭の `pure:publication` コメントとして本文と一緒に同期され、エディターには表示されません。別端末の古い公開設定が、取り下げ済みの記事を自動で公開し直すことはありません。設定の競合が表示されたら、R2 を同期するか、明示的に非公開へ戻してから公開し直してください。競合コピーは非公開で保存します。

R2 が有効な場合は、端末間の同期が完了してから GitHub を更新します。R2 に接続できない間は公開先の更新も待ち、再接続後に再試行します。公開済みの本文・画像・記事情報が同じなら、ファイルの更新日時だけが違っていても同期済みとして扱います。本文が異なる古い記事による上書きは引き続き防ぎます。

Mac・iPhone で濁点などのファイル名の内部表現（NFC / NFD）が違っても、同じパスとして比較します。同じ本文に対してファイル名の内部表現だけを理由に「新しい公開版があります」と判定したり、公開し直したりしません。

poin7s.com はページを開いた時点の公開一覧を読みます。すでに開いているページや GitHub の配信キャッシュには反映の遅れがあり得るため、更新後はサイトを再読み込みしてください。

公開したファイルを Finder 等で外から削除しても、GitHub の記事は自動では取り下げません。**取り下げは pure の公開切り替えから行ってください。** 公開先を変更する場合も、元の公開先で各記事を取り下げてから変更します。

## 保存形式

- `posts/<元の Markdown ファイル名>.md`: 公開本文。内部の公開設定コメントは含めません。
- `assets/<画像の SHA-256>.webp`: 公開記事が使用するローカル画像。複数記事で共有する画像は、最後の記事が取り下げられるまで保持します。
- `index.json`: タイトル、タグ、更新日時、本文・画像パスと公開設定の世代情報。非公開記事の一覧は含みません。取り下げた記事は ID と設定 ID だけが残り、古い端末からの再公開を防ぎます。

本文・画像・一覧は Git Database API で1つのコミットにまとめ、`force: false` で更新します。同時更新やファイルの変更が発生した場合は処理を止めて再同期します。サイト側にトークンは不要です。

公式仕様: [Git Database API](https://docs.github.com/en/rest/guides/using-the-rest-api-to-interact-with-your-git-database)、[Fine-grained token の作成](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。
